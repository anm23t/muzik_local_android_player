# DESIGN

Описание интерфейса для реализации. Источник: макет Figma «MUZIK PROJECT» (ключ файла `a87N0gGkMizBePmGLKq535`). Значения ниже сняты из макета, решения владельца проекта отмечены явно. Если макет и этот файл расходятся, нужно спросить владельца, а не выбирать самому.

## 1. Принципы

- Только тёмная тема. Это часть философии дизайна, светлой темы не будет.
- Рамка вокруг экрана (скруглённая, с отступом 24 px) является частью дизайна приложения. Внешние отступы адаптируются под устройство (системные панели, вырезы, размеры экрана).
- Акцентный цвет по умолчанию красный. Весь красный цвет в интерфейсе это акцент, и он меняется в зависимости от обложки (см. раздел 4).
- Нижние меню (футеры) на разных экранах отличаются сознательно из-за разного места и функций. Структуру и функции не менять, максимум выровнять размеры и отступы.
- Макет неполный: перетаскивание и нажатия предполагаются там, где их не нарисовали (например, перемотка по полосе прогресса и перетаскивание в очереди).
- Подкастов и аудиокниг в интерфейсе нет.

## 2. Токены

### Цвета (по умолчанию)
| Токен | Значение | Где используется |
|---|---|---|
| `background` | `#000000` | Фон экрана и рамки |
| `surface-elevated` | `#121212` | Кнопки-иконки, карточка обложки, мини-плеер, строки треков |
| `outline` | `#1F1F1F` | Границы, фон полосы прогресса |
| `text-primary` | `#FFFFFF` | Основной текст |
| `text-secondary` | `#9CA3AF` | Подписи, исполнители, время |
| `accent` | `#CD253E` | Динамический, см. раздел 4 |
| `accent-container` | `#241015` | Тёмный тон акцента: фон кнопок «Play», «Sort», «All Songs», «Готово», выбранной строки |
| `accent-shadow` | акцент, прозрачность 20% | Тень большой кнопки воспроизведения |

`accent-container` и `accent-shadow` вычисляются из `accent`, а не хранятся отдельно.

### Скругления
Внешняя рамка 32, карточки и обложка в плеере 24, мини-плеер и внутренняя обложка 16, обложки в списках и карточки треков 8, круглые кнопки (радиус равен половине размера), плашки-«таблетки» 999.

### Размеры
Кнопки-иконки 44 и 48, кнопки навигации 48, кнопки управления 56, большая кнопка воспроизведения 72, высота мини-плеера 64, строка трека 40, строка альбома 86, строка исполнителя 66, обложка в списке 70, в мини-плеере 40, в плеере 284x288, толщина полосы прогресса в плеере 8, в мини-плеере 2.

### Типографика
Шрифты из макета: **Playfair Display** (Regular, Bold) для заголовков и кириллических подписей и **Manuale** (Light, Regular, Medium, SemiBold, Bold) для остального текста. Размеры в макете: 40 (имя исполнителя), 28 (название трека в плеере), 20 (заголовки разделов), 18, 17, 16, 14, 13, 12.

Известные проблемы типографики в макете (не копировать):
- у ряда текстов размер 20 при высоте строки 14, в коде нужно задать нормальную высоту строки;
- Manuale, по данным каталогов шрифтов, не содержит кириллицы, а на Android без запасного шрифта кириллица уйдёт в системный (возможен диссонанс), и Manuale Light в этой семье отсутствует;
- вес и семейство для одинаковых по роли текстов различаются между экранами. Нужна единая шкала (заголовок, подзаголовок, основной, подпись).

Решение: Playfair Display для заголовков, Literata вместо Manuale для основного текста (оба под SIL OFL, оба поддерживают кириллицу). Manuale не используется. Файлы шрифтов лежат в репозитории вместе с текстом лицензии.

| Main Menu | `28:620` | Главная: плейлисты, продолжить прослушивание, слушаем сегодня, мини-плеер, нижнее меню (исполнители, альбомы, плейлисты, статистика) |

| Artist Card | `33:714` | Карточка исполнителя: фото, число песен, топ треков с числом прослушиваний, альбомы, кнопка All Songs |

Две копии списков (`Album List`, `Artist List`) являются вариантами одного экрана и должны быть одной реализацией.

### Поведение (решения владельца)
- Любая кнопка с иконкой дома открывает главную, независимо от названия слоя.
- Нажатие на мини-плеер открывает плеер (`Player Menu`).
- В плеере исполнители отображаются отдельными нажимаемыми элементами через запятую: каждый ведёт на карточку своего исполнителя. Это ключевая функция проекта, разбиение берётся из тегов и правил разбиения.
- Исполнитель альбома берётся из отдельного тега (исполнитель альбома), а у каждой строки трека показывается свой исполнитель (может отличаться от альбомного).
- «Local availability» в карточке альбома это просто число треков.
- Меню действий применяется к каждому треку отдельно (в строках треков, в плеере, в мини-плеере). Содержимое меню: добавить в любимое, оценить, играть следующим, добавить в очередь, добавить в плейлист (выбрать существующий или создать новый) и другое из обсуждённого функционала. Оценка по шкале 0.0-10.0 с шагом 0.1 (например, 6.7), хранится только в БД. Избранное тоже хранится в БД.
- Фото исполнителя пользователь добавляет вручную (любое по желанию): долгое нажатие на фото в карточке исполнителя. Без фото показывается заглушка.
- Число прослушиваний на карточках берётся из статистики за всё время использования приложения. Топ треков сортируется по убыванию.
- Рекомендации «Слушаем сегодня» строятся по статистике: давно не слушанное или слушанное мало.
- Названия «Rage Songs», «Soft Songs», «Happy Songs» это заглушки. Плейлисты для главной формируются по правилам из обсуждённого функционала (умные плейлисты, версия 1.4). До этого главная может показывать только «Продолжить прослушивание» и «Слушаем сегодня».
- «New sort» в диалоге сортировки это задел на будущее (добавление нового правила), в MVP не реализуется.

### Опции сортировки (решение ассистента, можно менять)
- Альбомы: по названию, по исполнителю, по году выхода, по количеству песен, по дате добавления.
- Исполнители: по имени, по количеству песен, по количеству прослушиваний, по дате добавления.
- Направление: повторное нажатие на выбранный пункт меняет порядок (по возрастанию/по убыванию), иконка на кнопке сортировки отражает направление.

### Ещё не нарисовано (будет добавлено владельцем)
Очередь, статистика, картинки для публикации, редактор тега и его точки входа, диалог оценки (шкала 0.0-10.0 с десятичными частями), режим множественного выбора в списке исполнителей с кнопкой «Remember as one artist» и диалогом порядка и написания имени, управление списком составных имён (добавить, удалить), меню действий трека и окно выбора плейлиста («Add to playlist»), тексты (LRC и TTML), «Проверка» исполнителей, настройки, запросы разрешений, прогресс сканирования, пустые и ошибочные состояния.

## 4. Динамический акцентный цвет

Весь красный цвет в интерфейсе (см. таблицу токенов) следует за обложкой.

Алгоритм:
1. Для играющего трека берётся обложка (из кэша маленьких обложек) и из неё выбирается доминирующий насыщенный цвет. Подходит `androidx.palette` или Material Color Utilities.
2. Цвет переводится в HCT, тон подгоняется так, чтобы акцент оставался читаемым на чёрном фоне (контраст не ниже 3:1 для элементов и 4.5:1 для текста). Насыщенность ограничивается сверху, чтобы не получить кислотные цвета.
3. Из акцента вычисляются `accent-container` (тёмный тон) и `accent-shadow`.
4. Результат кэшируется в БД вместе с альбомом (`album.accent_color`) и пересчитывается при смене обложки.
5. Запасной вариант: нет обложки, обложка почти чёрная, белая или серая (низкая насыщенность) то используется красный по умолчанию `#CD253E`.
6. Смена цвета при смене трека анимируется (плавный переход, порядка 300-500 мс).

Область применения: по решению владельца акцент следует за играющим треком по всему приложению, на каждом экране. Список элементов с акцентом: большая кнопка воспроизведения и её тень, заполнение полосы прогресса, кнопка паузы и полоса в мини-плеере, строка текущего трека и индикатор уровня, кнопки «Play», «Sort», «All Songs», «Готово» (рамка и фон), радиокнопка и выбранная строка в диалоге сортировки.

## 5. Реализация в коде

- Токены лежат в `core:designsystem`: цвета, формы, типографика, значения отступов.
- `accent` передаётся через `CompositionLocal`, чтобы любой компонент брал его из темы, а не из констант.
- Компоненты строятся по макету: круглая кнопка-иконка, плашка-кнопка, карточка, строка трека, мини-плеер, нижнее меню, диалог.
- Ресурсы (иконки) берутся как векторные из макета. Набор иконок в стиле Lucide (`arrow-down-wide-narrow`, `folder-check`, `list-music`, `users`, `disc`, `chart-column`, `shuffle`, `repeat`, `home` и др.): лицензию набора проверить перед подключением.
- Основной язык интерфейса английский, русский перевод вторичный. Русские подписи макета («Плейлисты для Вас!», «Продолжить прослушивание ?», «Слушаем сегодня ?», «Сейчас играет:») считаются русским переводом. Предложение для английских: «Playlists for you», «Continue listening», «Listen today», «Now playing» (подтвердить у владельца). Контент (названия, исполнители) отображается как есть, кириллица поддерживается шрифтами.

## 6. Исправления относительно макета (делать при реализации)

- Топ треков у исполнителя сортируется по убыванию числа прослушиваний (в макете значения заглушки идут не по порядку).
- Убрать пробел перед «?» и выровнять пунктуацию в заголовках.
- Задать нормальную высоту строки у всех текстов (в макете у части текстов размер 20 при высоте строки 14).
- Список прокручивается под мини-плеером с нижним отступом, чтобы последняя строка не обрезалась.
- Одинаковые по роли тексты используют одну типографическую шкалу, а не разные семейства и веса.
- Привести имена слоёв и функций кнопок в соответствие (все кнопки с иконкой дома ведут на главную) и выровнять нижние меню, не меняя их функций.
- Между исполнителями в плеере и в списках единый разделитель «, » без лишних пробелов.
