# CLAUDE.md

Инструкции для Claude Code. Читай этот файл в начале каждой сессии, затем `ARCHITECTURE.md` и `DATABASE.md`, когда задача касается архитектуры или данных, и `DESIGN.md`, когда задача касается интерфейса.

## Проект

Локальный музыкальный плеер для Android. Open-source (GitHub, лицензия GPLv3).
Главные отличия от других плееров:
- чтение и редактирование всех тегов (название, исполнитель, альбом, обложка, текст) с записью прямо в файлы;
- несколько исполнителей на трек: автоматическое разбиение и ручная правка, исполнители считаются по отдельности;
- статистика прослушиваний с экспортом данных.

## Стек

- Kotlin, Jetpack Compose (Material 3), Coroutines и Flow
- Media3 (воспроизведение, `MediaSessionService`)
- Room (SQLite), DataStore (настройки)
- Hilt (внедрение зависимостей)
- Теги: библиотека выбирается в задаче 0.3.0 (TagLib через JNI или JAudioTagger), решение фиксируется в `docs/decisions/`
- Тесты: JUnit 5, Turbine для Flow, Robolectric только где без него нельзя
- Без сервисов Google (Firebase, Play Services и т.п.), чтобы проект можно было собрать без них

## Модули

```
app/                  точка входа, навигация, DI-сборка
core/model/           чистый Kotlin: Track, Album, Artist, ListenEvent (без Android)
core/database/        Room: сущности, DAO, миграции
core/tags/            чтение и запись тегов, разбиение исполнителей
core/library/         сканирование MediaStore, индексация, кэш обложек
core/playback/        Media3: сервис, очередь, MediaSession
core/stats/           запись событий прослушивания, расчёт срезов, экспорт
core/designsystem/    цвета, шрифты, компоненты (из Figma)
feature/*/            экраны: library, player, tag-editor, artists, stats, playlists, settings
docs/                 README, CONTRIBUTING, ARCHITECTURE, DATABASE, decisions/
```

Правила зависимостей описаны в `ARCHITECTURE.md`. `feature:*` не зависят друг от друга, `core:model` не зависит ни от чего.

## Ключевые решения (не менять без обсуждения)

1. Теги читаются из файлов и пишутся в файлы. БД служит кэшем для поиска и сортировки и может быть пересобрана сканированием.
2. Запись в файл всегда через безопасную операцию: правки пишутся в рабочую копию в личной папке приложения, результат проверяется чтением (теги и аудиоданные), перед заменой оригинала создаётся резервная копия, при ошибке оригинал восстанавливается из неё. Замена оригинала это запись содержимого проверенной копии через дескриптор файла. Прямая правка оригинала библиотекой тегов запрещена.
3. Исполнитель это отдельная сущность. Связь трек-исполнители многие-ко-многим с порядком (`position`).
4. Статистика, оценки, избранное, алиасы исполнителей и составные имена живут только в БД и попадают в резервную копию (JSON).
5. Событие прослушивания хранит снимок названия и исполнителей, чтобы статистика переживала удаление и переименование файлов.
6. Отдельные роли (композитор, продюсер и т.п.) не поддерживаются сознательно.
7. Подкасты и аудиокниги в приложении не нужны вообще: сканер их отфильтровывает (флаги MediaStore для подкастов и аудиокниг, расширение `.m4b`, при необходимости папки с подкастами), в БД они не попадают, в интерфейсе нет ни разделов, ни настроек для них.
8. Синхронизированные тексты: форматы LRC и TTML (чтение, отображение с подсветкой строки, ручная синхронизация и запись).
9. Тема только тёмная (философия дизайна). Светлой темы нет.
10. Акцентный цвет динамический: весь "красный" в интерфейсе следует за обложкой играющего трека, по умолчанию красный. Подробности в `DESIGN.md`.
11. Фото исполнителей пользователь добавляет вручную (долгое нажатие на фото), из сети они не подтягиваются.
12. Разбиение исполнителей: если в строке есть `;`, режем по `;`, иначе по `,`. Других разделителей нет. Имена с запятой в псевдониме хранятся в таблице составных имён (встроенный JSON-список плюс пользовательские, встроенные можно отключать). Подробности в `ARCHITECTURE.md`, раздел 4.
13. Оценка трека 0.0-10.0 с шагом 0.1, хранится целым числом десятых только в БД.
14. Основной язык интерфейса английский, русский перевод вторичный. Шрифты: Playfair Display (заголовки) и Literata (основной текст), оба под SIL OFL.

## Правила кода

- Код должен быть понятен новому контрибьютору: небольшие функции, говорящие имена, KDoc на публичных классах и интерфейсах.
- Межмодульные границы только через интерфейсы и модели из `core:model`.
- Бизнес-логика не лежит в Composable-функциях. Экран получает состояние из ViewModel (`StateFlow`), отправляет в неё события.
- Работа с файлами и БД только вне главного потока (диспетчеры внедряются через DI для тестов).
- Никаких новых зависимостей без согласования: сначала предложи, объясни зачем и каков вклад в размер APK.
- Строки интерфейса только в ресурсах (`strings.xml`), без литералов в коде. Базовый язык ресурсов: английский, русский перевод рядом.
- Стиль: ktlint/detekt, конфигурация в корне. Перед коммитом код должен проходить линтер.

## Тесты

- Логика без Android (разбиение исполнителей, нормализация имён, расчёт статистики) покрывается юнит-тестами обязательно, с таблицей граничных случаев.
- Для тегов есть набор эталонных файлов в `core/tags/src/test/resources/` (маленькие, без защищённого авторским правом контента).
- Новая функциональность без тестов не принимается.

## Порядок работы над задачей

1. Прочитай описание задачи в `ROADMAP.md` и затронутые модули.
2. Предложи план из нескольких шагов, дождись подтверждения.
3. Реализуй с тестами, не выходя за список модулей задачи.
4. Прогони тесты и линтер.
5. Кратко опиши, что сделано и что осталось. Коммит делает пользователь или ты по его просьбе.

## Коммиты

Conventional Commits: `feat(tags): ...`, `fix(library): ...`, `test(stats): ...`, `docs: ...`. Один коммит на законченный логический шаг.

## Чего не делать

- Не менять схему БД без миграции и теста миграции.
- Не форматировать и не переименовывать файлы вне задачи.
- Не писать в файлы пользователя без безопасной операции и проверки.
- Не добавлять сетевые запросы без явной настройки "включено" (по умолчанию приложение работает офлайн).
- Не вставлять в репозиторий музыку, обложки и тексты, защищённые авторским правом.
