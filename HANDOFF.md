# HANDOFF: переход из чата в Claude Code

Этот файл передаёт контекст проекта из обсуждения в чате. Прочитай его целиком, затем `CLAUDE.md`, `ARCHITECTURE.md`, `DATABASE.md`, `ROADMAP.md` (и `PLAN.md`, если он лежит в репозитории). Пользователь общается по-русски, отвечай по-русски. Код, идентификаторы и коммиты по-английски.

## 1. Что строим

Локальный музыкальный плеер для Android, open-source, публикация только на GitHub. Репозиторий и код пока не созданы, написана только документация.

Ключевые функции:
- парсинг всех тегов из файлов (название, исполнитель, альбом, обложка, текст) и ручное редактирование внутри приложения;
- правки тегов записываются в сами файлы (так сделано в Poweramp, пользователю такой подход нравится);
- несколько исполнителей на трек: разбиение автоматически (парсинг) или вручную, исполнители считаются по отдельности (у Poweramp пользователь считает эту часть реализованной плохо);
- статистика прослушиваний, красивое оформление, экспорт данных;
- понятный код, чтобы проект могли дорабатывать другие.

Дизайн: пользователь проектирует макет в Figma. Сейчас макета ещё нет, он нужен хотя бы для основных экранов (библиотека, плеер) к версии 0.2. Для чтения макета можно использовать Figma-коннектор.

## 2. Принятые решения

| Тема | Решение |
|---|---|
| Платформа | Android (основная и единственная пока) |
| Стек | Kotlin, Jetpack Compose, Media3, Room, Hilt, Coroutines/Flow (рекомендован ассистентом, пользователь согласился с планом) |
| Go | Рассматривался и отвергнут: фоновое воспроизведение, MediaStore и запись тегов требуют Android API, для записи тегов нет хороших Go-библиотек |
| Теги | Пишутся в файлы, БД это кэш |
| Исполнители | Отдельная сущность, связь с треком многие-ко-многим с порядком |
| Алиасы | Кнопка "Проверка": нормализация имён, группы вариантов, предпросмотр, выбор верного написания (самое частое в библиотеке), решения запоминаются в таблице алиасов |
| Лицензия | GPLv3 (рекомендована, финальное подтверждение от пользователя нужно перед первым коммитом) |
| Распространение | Только GitHub Releases, без Google-зависимостей |
| Размер APK | Прогноз 10-20 МБ на версии 1.0 (R8, сжатие ресурсов, сборки по архитектурам) |

## 3. Что пользователь явно отверг

- Отдельные роли (композитор, продюсер, автор текста).
- Изменение скорости и тона.
- Повтор участка A-B.
- Виджеты на домашний экран допустимы только очень поздно (версия 2.0).

## 3a. Добавлено позже

- Синхронизация текстов поддерживает не только LRC, но и TTML (версия 1.5).
- Макет Figma готов частично: нет страницы очереди и страницы статистики, а также картинок для публикации, которые генерируются из статистики. Их нужно доделать до версий 0.2 (очередь) и 0.6-1.4 (статистика и карточки). Экран настроек нужен до версии 0.5.
- Макет Figma "MUZIK PROJECT", ключ файла `a87N0gGkMizBePmGLKq535`. Описание токенов, экранов, поведения и динамического акцента лежит в `DESIGN.md`.
- Решения по макету: только тёмная тема, красный акцент динамический по обложке на всём приложении (для чёрно-белых и серых обложек остаётся красный), рамка части дизайна, фото исполнителей вручную (долгое нажатие), число прослушиваний из статистики.
- Разбиение исполнителей: по `;`, иначе по `,`. Имена с запятой в псевдониме (например, «Tyler, The Creator») хранятся в таблице составных имён: встроенный JSON-список плюс пользовательские, пользователь добавляет их кнопкой «Remember as one artist» (множественный выбор, диалог порядка и написания) и может удалять, встроенные при удалении отключаются.
- Оценка трека 0.0-10.0 с шагом 0.1, только в БД.
- Основной язык интерфейса английский, русский вторичный. Шрифты: Playfair Display и Literata.

## 4. Что пользователю понравилось

Gapless, crossfade, эквалайзер, умные плейлисты, статистика с разбиением по исполнителям, карточки для публикации. Возобновление воспроизведения оставлено в минимальном виде: восстановление очереди и позиции при запуске. M3U/M3U8 перенесены на этап плейлистов (1.1).

## 5. Версии

0.1 каркас и библиотека, 0.2 фоновое воспроизведение, 0.3 теги (чтение и запись), 0.4 несколько исполнителей и алиасы, 0.5 воспроизведение и настройки (gapless, ReplayGain, crossfade), 0.6 статистика, 1.0 MVP с интерфейсом по макету. Далее 1.1-1.5 и 2.0. Подробности и задачи в `ROADMAP.md`.

## 6. Как пользователь работает с Claude Code

- Подписка Pro, лимиты общие с чатом (пятичасовое окно плюс недельный лимит). Доступность Opus на Pro нужно проверить командой `/model`.
- Поэтому: одна небольшая задача на сессию, план перед кодом (plan mode), коммит после задачи, `/clear` между задачами, Opus для сложных мест, Sonnet для рутины.
- Сборку и запуск на устройстве выполняет пользователь, агенту отдаёт первые строки ошибок.
- `ANTHROPIC_API_KEY` не должна быть задана, иначе пойдёт платное API.
- Рекомендованные плагины: KotlinSense (или kotlin-lsp) и Code Review.

## 7. Открытые вопросы (решить в начале)

1. Название приложения и package id: решено, Muzzzlo (`app_name`), `org.muzzzlo.player` (`docs/decisions/006-min-sdk-and-package.md`).
2. Минимальная версия Android: решено, API 26 (`docs/decisions/006-min-sdk-and-package.md`).
3. Библиотека для тегов: решено в задаче 0.3.0, TagLib через JNI (`docs/decisions/005-tag-library.md`).
4. Лицензия: решено, GPLv3 (`LICENSE`).
5. Когда будет готов макет Figma и в каком виде он будет передан (ссылка через коннектор или экспорт).

## 8. С чего начать

1. Пользователь выполняет подготовку из `PLAN.md` раздел 2 (Android Studio, репозиторий, лицензия, пустой проект, тестовые аудиофайлы).
2. Положить в корень репозитория `CLAUDE.md`, `ARCHITECTURE.md`, `DATABASE.md`, `ROADMAP.md`, `HANDOFF.md`.
3. Первая задача: 0.1.1 (модули, зависимости, version catalog, ktlint/detekt, CI, выбор минимальной версии Android). Начни с плана в plan mode и дождись подтверждения пользователя.
4. После закрытия вопросов из раздела 7 зафиксировать решения в `docs/decisions/`.

## 9. Принципы, которых держаться

- Безопасная запись тегов: временная копия, запись, проверка чтением, замена.
- Никаких новых зависимостей без согласования.
- Тесты обязательны для логики разбиения исполнителей, нормализации имён и статистики.
- Не расширять объём: функции вне текущей версии не добавлять.
